# 設計

## 合意した要件

- 作成先: `/Users/a3140236/develop/works/endoscope_degrid`。
- CPUで実行するPython CLI。単一動画・一括処理・短区間・比較画像・設定・レポート。
- 忠実性を優先し、学習モデルによる細部生成を避ける。均一面の校正画像はない。
- 方式比較後、周波数選択除去Aを標準、標本再構成Cを選択肢とする。
- 8-bit H.264 MP4/MOVに正式対応。入力の解像度、走査方式、時間軸、音声を維持。
- 映像の再圧縮は画質優先、音声はコピー。最初の指定動画は全編を書き出す。

## モジュール

| ファイル | 役割 |
|---|---|
| `degrid.py`, `src/endoscope_degrid/cli.py` | 引数、単一／一括処理、エラー、レポートの統括 |
| `src/endoscope_degrid/algorithms.py` | 格子の校正、ノッチ設計、コア再構成。動画I/Oから独立 |
| `src/endoscope_degrid/media.py` | 検査、時刻とフィールド順、映像再圧縮、音声コピー、出力検証 |
| `src/endoscope_degrid/reporting.py` | 比較画像、周波数図、校正配列、JSON |
| `tests/` | 合成格子の復元と動画の時間軸・音声・キャンセル等 |

## データフロー

1. 入力を全デコードして、破損・時刻・実フレーム数を確認する。同時に校正フレームを抽出する。
2. 動画ごとに、走査方式に対応する1枚または2枚の周波数マスクを生成する。
3. 全編または指定区間をストリーミング処理する。全フレームを画像ファイルとして保存しない。
4. 入力表示時刻の差からエンコーダの時間単位を決め、CFR/VFRとも正確なPTSを割り当てる。
5. 音声はパケットをコピーし、内容と時刻の署名を計算する。
6. 一時動画を閉じて読み直す。各フレームのPTSと数、長さ、走査方式、フィールド順、音声の署名を照合する。
7. 検証成功後に最終出力名へ変更する。失敗・キャンセルでは未完成動画を除去する。

時刻・画素アスペクト比の保持を優先し、入力の宣言上の59.94とデコード後29.97を単純に同一視しない。
出力のH.264内部表現やコンテナのフレームカウント表示が変わっても、実際のフレーム時刻とフィールド順が一致することを検証する。

## 意図的な制限

- 画像の真の正解はないため、自動指標だけで格子除去後の細部の忠実性を認定しない。
- 自動校正は近似六角格子を前提とする。格子が検出できない素材には自動で別方式を適用しない。
- 動画中で光学倍率・視野位置・格子間隔が変わる場合は区間ごとの入力が必要。自動のシーン分割は行わない。
- 未対応のストリームを黙って捨てない。字幕・データ等があれば停止する。
- 正式なUIはCLI。ネットワークサービスやバックグラウンド監視は持たない。
